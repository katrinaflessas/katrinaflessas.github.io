So far, I actually like TypeScript, although I am still getting used to the syntax. I already had experience with Java, C, and C++, so concepts like loops, functions, classes, and objects were not completely new to me. The main adjustment has been learning how TypeScript writes and organizes those concepts. This module gave me more practice with type annotations, arrays, constructors, methods, and features such as arrow functions. Some of the syntax still feels strange at finder, especially when there are multiple types or objects involved, but it is starting to make more sense with repetition.

From a software engineering perspective, I think TypeScript is a good programming language. One feature I like is that it lets you specify what type of value a variable, parameter, or function should use. This can catch mistakes before the program runs and makes it easier to understand what each part of the code is supposed to do. I can see how that would be helpful when working on a larger project or sharing code with other people. I also like that TypeScript has some similarities to languages I have already used while still introducing me to a different way of writing code.

I found the practice WODs useful because they gave me repeated practice with the same concepts. Repetition is probably the most helpful part for me because I usually understand something better after I have worked through it multiple times. The WODs helped me become more familiar with TypeScript syntax and gave me practice figuring out how to structure a solution. I could also look back at mistakes from one attempt and try to avoid making them again.

However, I do not really like the timed part of athletic software engineering. I am a perfectionist, and I prefer to thoroughly learn each step before I feel pressured to complete something quickly. When I know a timer is running, I start focusing too much on the time and worrying about whether I will finish. Sometimes that makes my mind go blank, even when I understand the basic idea behind the problem. Because of that, the timer can make coding feel more stressful than enjoyable for me.

I personally prefer programs like Codecademy because they explain concepts step by step and let me practice them without feeling rushed. I think the repetition involved in athletic software engineering can work for me, but I would rather practice without a timer until I understand the process and then work on improving my speed. I may become more comfortable with timed WODs as I gain experience, but right now I learn better when I can slow down, understand why each step works, and make sure I am doing it correctly before moving on.
